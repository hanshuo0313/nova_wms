## 三、业务规则实现

| 规则 | 实现位置 |
| --- | --- |
| 动碰次数：出入库/移库 +1，盘点后清零 | `InventoryService.add/subtract` 增加计数；`CheckOrderService.check` 调用 `resetMoveCountBySku` 清零 |
| 采购单确认后自动生成采购入库单 | `PurchaseOrderService.confirm` → `ReceiptOrderService.syncPurchaseReceipt` |
| 采购单修改同步采购入库单 | `PurchaseOrderService.updateByBo` → `syncPurchaseReceipt`（已入库的不再同步） |
| 采购入库完成自动关闭采购单并回写入库数量 | `ReceiptOrderService.receive` → `completePurchaseOrder`（状态置 3 已关闭，明细 `inbound_quantity`/`actual_quantity` 更新） |
| 领料返库数量 ≤ 领料出库数量，且必须关联出库单 | `ReceiptOrderService.validateBeforeReceive`（入库类型 2） |
| 退货单只能关联已完成采购单，退货数 ≤ 实收数量，可多次退货 | `ReturnOrderService.availableDetails`（实收 − 已退）与 `complete`（扣库存、回写退货数量、生成退货出库单） |
| 盘点方式：全盘/动盘/指定 | `CheckOrderService.generateDetails`（全盘=仓库全部库存；动盘=`move_count>=1`；指定=供应商/物料/货位） |
| 安全库存预警（按仓库） | `GET /wms/inventory/alert`，条件 `item.safety_stock > 0 且 inventory.quantity < item.safety_stock` |

## 七、已知限制

1. 库存模型按「仓库 + SKU」汇总，同仓库内不同货位之间移库不会改变库存数量（原项目模型限制）。

## 十、第三轮调整（2026-11-22 深夜）

### 1. 采购单号自动生成

现象：新增采购单提示「采购单号不能为空」。
原因：`GET /wms/purchaseOrder/generateNo` 使用 `R.ok(String)`，Java 命中 `ok(String msg)` 重载，单号被放进 `msg`，前端读 `data` 得到空值。
修复：改为 `R<String> r = R.ok(); r.setData(...)`（退货单 `generateNo` 同样修复）。新增采购单弹窗现已自动带出 `CG2026…`。

- WmsPage 增加 `max-height` 属性与 `#detail` 插槽；表格高度 = 行数 × 41 + 表头，并受可用高度/最大高度双重限制。

### 3. ID 列表头全选

## 十二、第五轮调整（2026-11-22 深夜）

### 1. 入库单部分上架不关单

- `wms_receipt_order_detail` 新增 `operated_quantity`（明细已上架/已入库数量）。
- 每次执行上架按明细累计操作数量；**所有明细的操作数量 ≥ 计划数量**才把入库单置为「已入库」并自动关闭，
  否则保持「未入库」，可继续上架；上架数量超过计划数量会被拒绝（“上架数量不能超过计划数量”）。

### 2. 退货单创建报错修复

现象：创建退货单提示「文件名或填写内容过长」。
根因：自动生成的退货出库单号 `THCK + 退货单号` 超过 `wms_shipment_order.order_no varchar(22)`，MySQL 报 Data too long。
修复：出库单号改为 `TH + 退货单号`（21 位），创建退货单与自动生成退货出库单均正常。

### 3. PAD 入库「上架」界面

PAD 入库改为两步：入库单列表 → 选择单据进入「入库上架」界面；按货位 + 物料逐条上架，三种状态提示：
- 匹配到待上架物料 → **上架中**（显示计划/已上架/剩余，可填上架数量）
- 物料不在该入库单 → **入库单中无对应物料的上架任务**
- 该物料剩余为 0 → **所选物料已上架完成**

上架成功后刷新明细进度；全部上架完成后入库单自动关闭并提示返回列表。
